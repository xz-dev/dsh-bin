## Why

仅切换 dsh 与插件环境，无法保留不同 dsh 版本所需的配置和凭据格式。数据位置又随真实程序位置、安装方式与显式覆盖而变化，不符合多数软件的固定目录习惯；用户需要能解释路径来源与当前选择的快速排障入口，而不只是目录清单。

本变更是 `split-dsh-manager` 的独立后续变更；不向正在实施的前置变更追加任务或改写其产物。

## What Changes

- 增加包含配置与内建本地凭据库的独立、可写、可选配置快照，按 dsh 运行包版本分组。创建、编号、别名、默认选择、复制、空快照、跨版本使用、使用保护及删除规则与插件环境快照一致。
- 插件快照继续位于 `<管理数据根>/snapshots/`；配置快照固定在 `<管理数据根>/config-snapshots/`，不跟随 `DSH_HOME`。两类内容、计数和选择互相独立。
- **BREAKING**：提案采用 `dsh manager snapshot <plugins|config> new|list|remove`，类型必填；不增加旧的无类型管理子命令别名。现有启动选择参数 `--snapshot` 仍仅指插件快照，新增对等的 `--config-snapshot`。
- **BREAKING**：受管理启动的配置、凭据读写和应用自身的配置导入／格式转换，改为只作用于所选配置快照。`DSH_HOME` 保留应用 home 及非快照应用数据的职责，不能作为所选配置缺失时的回退来源。
- 扩展运行包启动协议，使运行包明确消费插件快照与配置快照的不同路径；不把管理引擎放回运行包。不支持新契约的运行包明确拒绝受管理启动，不能忽略配置快照后继续运行。
- 增加只读 `dsh manager path` 总览及 `self/home/runtime/snapshot/addon/cache/tmp/completion` 八类查询，提供绝对路径、解析来源、有效选择、问题状态与 JSON 输出，辅助排查位置变化、选择失效和目录冲突。查询不初始化、不联网、不执行应用／插件／shell，不读取配置或凭据正文。
- 以共享生命周期的参数化 BDD 场景和真实进程 E2E 验证行为，并验证真实应用的配置／凭据读写隔离，而非只检查目录存在。

## Capabilities

### New Capabilities

- `configuration-snapshots`：版本分组的独立配置／凭据集合、与插件快照的行为对等、实际读写隔离和凭据保护。
- `manager-paths`：八类路径查询、总览、精确对象定位与无副作用输出。

### Modified Capabilities

以下能力由前置 `split-dsh-manager` 提供。目前 `openspec/specs/` 尚无主规格，本变更的 MODIFIED 增量以其同名增量规格为明确的依赖基线；不是声称这些能力已经归档或实施完成。必须先验收并归档前置变更，再校对并应用这些增量。

- `manager-control`：增加 path 与类型化快照命令、配置快照选择，以及两类快照的独立生命周期和保护。
- `portable-storage`：明确配置快照属于管理器数据根，局部修订显式 `DSH_HOME` 对受管理配置／凭据位置的控制。
- `runtime-bundles`：扩展启动协议、配置路径消费与重启保护，防止应用继续使用共享配置／凭据。

## Impact

- 前置依赖：`split-dsh-manager` 的独立 Zig 管理器、存储上下文、运行包协议、使用保护、补全注册记录与真实进程测试框架。前置未验收、主规格未就绪时，不启动本变更实施或规格同步。
- 管理器受影响区域：`dsh-manager/src/` 中命令分发、选择、快照存储、启动上下文、状态查询与补全；不引入 YAML／凭据解析器。
- 构建侧受影响区域：`dsh-bun-build/runtime/` 的薄启动适配、`scripts/transform-app.mjs` 的路径适配和构建检查，以及运行包元数据／协议声明。
- 验收与文档：`dsh-manager/test/`、`dsh-bun-build/test/`、真实运行包 E2E、CLI 帮助与项目说明。开发测试可使用现有 JS 工具，交付的管理操作仍不依赖宿主 Node/Bun。
- 不包括实现、发布、旧 release 删除、shell 实际注册、凭据导出／云同步、旧耦合运行包兼容、共享 home 的自动迁移，或对任意插件外部路径的通用发现。
