## Purpose

为不熟悉本项目的用户提供管理器能够确定的目录和文件位置，区分程序、管理状态、应用 home、各版本运行包与两类快照。由于位置随真实程序路径、安装方式和显式覆盖而变化，查询同时是快速排障入口，必须解释路径来源、有效选择及可观察的路径冲突，而不是仅打印目录清单。查询在空安装和离线环境可用，不通过初始化或执行应用来制造结果。

## ADDED Requirements

### Requirement: 八类受管理路径与目录总览

`dsh manager path` SHALL 提供不带子命令的目录总览，以及 `self`、`home`、`runtime`、`snapshot`、`addon`、`cache`、`tmp`、`completion` 八类查询。总览 SHALL 展示管理器已知的主要根目录与位置来源；具体对象由对应查询展开。`self` SHALL 区分真实可执行文件、管理数据根和管理器配置／状态目录；`home` SHALL 显示有效应用 home 及默认或显式 `DSH_HOME` 来源，不得称其为受管理配置／凭据的活动存储位置。配置快照始终属于管理数据根的 `config-snapshots/`。

#### Scenario: PATH-OVERVIEW 总览区分三种职责
- **WHEN** 用户设置外部 DSH_HOME 后执行无参数 path、path self 和 path home
- **THEN** 输出区分管理器状态、外部应用 home、管理数据根内的配置快照存储根，不把三者合并为一个“配置目录”

### Requirement: 排障可解释路径来源与有效选择

路径总览 SHALL 同时解释真实管理器位置、便携或托管安装模式、管理数据根的解析依据、应用 home 的覆盖来源，以及能够只读解析的有效运行包、插件快照、配置快照和 addon 组合。当前有效对象 SHALL 标明来自显式单次参数、持久固定引用或默认最新项；不能把“已安装对象清单”冒充“下一次启动会使用的对象”。无参数总览可接受管理器既有前置选择参数以检查单次启动意图，但 MUST NOT 初始化缺失对象。没有安装时应说明尚无有效组合；固定引用失效、目录类型冲突或所有权冲突时应保留可确定的位置并报告原因，不能默默换位置。不得扩展为自动修复、全环境变量转储或健康检查脚本执行。

#### Scenario: PATH-EXPLAIN 解释为什么落在这个目录
- **WHEN** 用户通过软链接启动便携管理器，或通过包管理器启动，并设置相对 DSH_HOME 后查询路径
- **THEN** 输出说明实际程序路径、安装模式、数据根依据，以及应用 home 相对哪个调用目录解析；不把软链接目录或普通 cwd 当成管理数据根

#### Scenario: PATH-CURRENT 库存与实际选择可区分
- **WHEN** 多个运行包和两类快照并存，用户先查询默认总览，再用前置 --use 与 --config-snapshot 查询单次意图
- **THEN** 两次总览分别报告可解析的有效组合和选择依据，结果与对应真实启动的选择一致，但不修改持久选择或创建缺失快照
- **AND** 固定引用已失效时报告该引用无法解析，保留静态目录诊断，不改选 latest

#### Scenario: PATH-CONFLICT 冲突不被修复掩盖
- **WHEN** 管理器预期的数据目录实际是文件，或是无法确认归本工具所有的非空目录
- **THEN** 查询指出目标绝对路径、预期角色和冲突原因，不能将其冒充有效安装、删除内容、补写所有权标记或切换到另一个根

### Requirement: 按本地对象查询绝对路径

`path runtime [版本]` SHALL 列出所有已安装运行包或指定本地运行包的绝对目录。`path snapshot [plugins|config] [ID或别名]` SHALL 列出两类、某类或该类的精确对象；指定对象时类型必填。`path addon [名称[:版本]]` SHALL 展示本地 addon 的名称、版本、兼容 slot 与绝对目录。过滤与匹配 SHALL 沿用相应本地管理命令的精确标识、别名及无歧义版本匹配规则；不会查询远程可用版本。不存在、歧义或非法的明确目标 MUST 非零退出，不打印一个看似已安装的猜测目录。

#### Scenario: PATH-RUNTIME 查询并存版本
- **WHEN** A、B 已安装，用户先执行 path runtime，再指定 A 的无歧义本地版本标识
- **THEN** 前者列出 A、B 的真实安装目录，后者只返回解析到的 A 及其绝对目录，不改变选择

#### Scenario: PATH-SNAPSHOTS 两类同号快照和孤立版本快照可见
- **WHEN** plugins 与 config 均存在 A@1，而 A 的运行包已经卸载
- **THEN** path snapshot 仍分别列出两个带类型的 A@1；path snapshot config A@1 只定位配置快照
- **AND** 查询不因 A 未安装而隐藏、清理或重新创建这些快照

#### Scenario: PATH-ADDONS 不混淆 addon 版本与 slot
- **WHEN** 本地有同名 addon 的多个版本及不同兼容 slot，用户查询 path addon 或按名称过滤
- **THEN** 每个本地对象有明确版本、slot 和绝对目录，缺失的明确版本不会触发下载

#### Scenario: PATH-TARGET-ERROR 明确目标不能静默回退
- **WHEN** 用户指定不存在的运行包、歧义前缀、不存在的配置快照，或未带类型的快照 ID
- **THEN** 查询明确失败，不选择 latest、不创建目录、不修改状态

### Requirement: 缓存临时目录与补全外部接入可发现

`path cache` SHALL 分别展示管理器缓存根、应用默认缓存根及管理器已确定的受控缓存路径；位置重合时保留角色说明。应用默认缓存位置 MUST 标为默认位置，不保证覆盖插件的显式外部配置。`path tmp` SHALL 展示管理器控制的临时工作根，不将其中的恢复中事务描述成可随意删除。`path completion [shell]` SHALL 读取注册记录，显示曾由管理器登记的脚本和 shell 配置接入路径及存在状态；没有记录时显示未注册，不猜测用户手工安装或当前 shell 已加载情况。

#### Scenario: PATH-CACHES 外部 home 的缓存被单独标明
- **WHEN** 管理器数据根为 R，显式应用 home 为 H，用户查询 path cache 与 path tmp
- **THEN** 输出分别说明 R 下的管理缓存、H 下的应用默认缓存和管理器临时根，不把它们混称为同一目录，也不删除残留

#### Scenario: PATH-COMPLETION 只报告登记位置而不执行 shell
- **WHEN** 一种 shell 有登记接入文件，其中一个已被用户移走，另一种 shell 没有注册记录
- **THEN** 查询分别返回登记文件的存在或缺失状态，以及未注册状态，不读取 shell 配置正文、不运行 shell 或生成安装动作

### Requirement: 输出区分存在未知与尚未创建

所有已确定路径 SHALL 使用与运行及维护操作一致的绝对路径解析，不缩写为 tilde、环境变量或相对路径。静态根目录未创建时 SHALL 仍可显示其计算位置并标明未创建。无法判断存在性、元数据损坏或权限不足 SHALL 明确标为无法确定／不可读取，不能伪装成不存在；必要的枚举无法完成时非零退出，已知总览仍可提供诊断。目录总览不得声称当前已选中一个尚未创建的快照。

#### Scenario: PATH-MISSING 冷安装显示未来根而不创建
- **WHEN** 数据根尚不存在，用户执行 path self、home、cache、tmp 和 path 总览
- **THEN** 已确定的绝对根路径标为未创建，没有任何新文件；对象列表为空，不分配快照编号

#### Scenario: PATH-UNREADABLE 不把错误当成空目录
- **WHEN** 某个查询目录不可读取或对象元数据损坏
- **THEN** 输出区分无法确定与不存在，并明确报告查询不完整，不用其他安装的目录补齐

### Requirement: 路径查询是离线无副作用操作

所有 path 查询及错误路径 MUST NOT 创建目录、持有需要创建文件的维护锁、保存选择、更新计数、写入注册状态、下载、联网、启动应用／插件／shell、触发首次引导或输出配置／凭据正文。实现 SHALL 只读取必要的管理元数据和文件系统路径信息，不解析应用配置以发现自定义位置。正常的文件读取访问时间变化不属于应用主动状态写入。未知插件外部目录、会话后端自定义 root、外部凭据后端以及手工 shell 接入 MUST NOT 被宣称为完整发现。

#### Scenario: PATH-READONLY 空安装和损坏选择都不引导
- **WHEN** 在隔离 HOME、无 Node/Bun、拒绝网络且运行包入口不可执行的环境，分别对空安装和损坏选择执行八类查询
- **THEN** 可确定的位置仍可显示，不能确定的对象明确报错；没有子进程、引导提示或应用主动文件写入

#### Scenario: PATH-SECRET 查询不打开敏感正文
- **WHEN** 配置／凭据和 shell 配置中放置专用测试秘密，并监测这些文件的打开操作后执行全部 path 查询
- **THEN** 查询不打开这些正文文件，stdout、stderr 和 JSON 都不包含测试秘密；仅管理元数据与路径存在性查询被使用

### Requirement: 便携托管和机器可读输出一致

路径查询 SHALL 复用真实程序定位、移动后相对数据根、显式 DSH_HOME 解析以及 Gentoo／Scoop 托管位置规则。所有查询 SHALL 支持 `--json`，返回带角色、绝对路径、位置来源、解析依据和状态的结构化记录；对象记录还包括类型、身份和版本等必要元数据，总览还包括可解析的有效选择或无法解析的原因。JSON 与人类输出 SHALL 描述同一组位置；非结构化诊断写 stderr，JSON 可在专用 diagnostics 字段携带结构化原因，stdout 不能混入引导或日志正文。

#### Scenario: PATH-MODES 安装方式不产生第二套路径算法
- **WHEN** 分别从软链接入口、移动后的便携安装、Gentoo 和 Scoop 托管安装查询路径，并覆盖显式相对 DSH_HOME
- **THEN** 返回实际运行和维护会使用的位置；普通 cwd 不改变管理数据根，只有显式相对 DSH_HOME 按调用 cwd 解析

#### Scenario: PATH-JSON 人类与 JSON 输出一致
- **WHEN** 对同一已知布局和未创建布局分别执行八类查询及对应 --json 查询
- **THEN** 两种输出的角色、身份、绝对路径和状态一致，JSON 可直接解析，无 ANSI 控制码、提示文字或凭据内容
