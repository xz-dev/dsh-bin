## MODIFIED Requirements

### Requirement: 兼容性由格式与启动协议表达

运行包 SHALL 声明格式版本、运行包身份、上游来源、平台、启动协议和所需内容，不以某个管理器发行版本号相等作为兼容条件。管理器 SHALL 在激活和启动前验证兼容性；旧耦合格式、不支持的协议和缺失必需内容 MUST 明确拒绝，不能尝试执行旧 bundle 的管理代码进行转换。受管理配置快照 SHALL 要求运行包明确支持同时消费插件根、配置根和应用 home 的新启动契约，不能在旧协议下添加一个可能被忽略的配置字段后宣称隔离已经生效。

#### Scenario: RB-INDEPENDENT 同一运行包配合不同管理器
- **WHEN** 两个独立发布的管理器支持同一启动协议并启动同一运行包
- **THEN** 无需重新构建该运行包，双方均能按协议启动它

#### Scenario: RB-LEGACY 拒绝旧格式
- **WHEN** 安装源提供旧的 launcher 与 bundles 混合归档
- **THEN** 管理器报告不支持的格式，不执行归档中的程序、不迁移用户数据

#### Scenario: RB-CONFIG-PROTOCOL 不能让旧运行包忽略配置根
- **WHEN** 运行包仅声明前置协议，不能消费独立配置快照，而用户尝试受管理启动
- **THEN** 管理器在执行该入口前明确拒绝并说明需要支持新协议的运行包；不降级为共享 home 模式
- **AND** path 和本地管理查询仍可用，不为了查询而启动或重建运行包

### Requirement: 应用仅消费已确定的启动环境

受管理的运行包 SHALL 消费管理器提供的运行包、插件快照、配置快照、应用 home、addon 与缓存位置，不自行重新选择 latest、创建快照或回退到其他安装。插件文件、配置及内建本地凭据、非配置类应用数据 SHALL 分别使用明确传入的位置，不能根据快照父目录层数或共享 home 推断配置根。配置适配 SHALL 覆盖加载、写入、监视重载和设置导入，而非仅改变一个显示字段。启动上下文缺失的独立应用运行保持原有上游行为；存在但缺失或损坏必要字段的受管理上下文 MUST 拒绝。

#### Scenario: RB-HOME 快照与应用 home 分离
- **WHEN** 管理器传入数据根内的插件快照 P、配置快照 C，以及外部 DSH_HOME
- **THEN** 插件取自 P，配置与内建本地凭据取自 C，应用 home 保持显式外部位置，不写错误的相邻 profiles 目录

#### Scenario: RB-CONFIG-CONTEXT 配置上下文缺失不能降级
- **WHEN** 新协议载荷缺少配置快照位置或该位置与传入身份不一致
- **THEN** 运行包在加载应用配置和凭据前拒绝，不尝试共享 home、最新快照或目录祖先位置

### Requirement: 重启保持当前运行上下文

应用内重启 SHALL 保持当前运行包、插件快照、配置快照和 addon 的已解析选择，而不是重新读取用户此后修改的默认选择。受管理的 runtime 进程 SHALL 在生存期保护其运行包和两类快照，即使 Windows 上的管理器等待进程提前退出，也不能因此将仍运行的 runtime 及其快照视为可删除。该保护不扩展为对任意孤立子进程的保证。

#### Scenario: RB-RESTART 改默认选择不改变已有会话
- **WHEN** 会话使用运行包 A、插件 P1 和配置 C1，用户把默认组合改为 B/P2/C2，然后原会话内部重启
- **THEN** 重启仍使用 A/P1/C1，新默认只影响新普通启动，A、P1 和 C1 的使用保护仍有效

### Requirement: 运行包更新由管理器拥有

受管理运行包 SHALL 保持只读，应用的上游自更新路径 MUST NOT 替换受管理运行包或管理器。插件依赖安装仍由 dsh 在所选插件快照内执行；用户配置修改及内建凭据更新只写所选配置快照。管理器只存储和选择副本，不替应用自动修复插件依赖或转换配置格式。

#### Scenario: RB-PLUGIN 插件安装不修改应用映像
- **WHEN** 用户通过受管理 dsh 安装真实插件并修改其开关或配置
- **THEN** 插件依赖进入所选插件快照，配置修改进入所选配置快照，运行包文件内容、其他快照和管理器版本不变
